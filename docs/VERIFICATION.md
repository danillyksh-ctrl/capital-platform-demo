# Отчёт о повторном аудите перед публикацией

Дата: 26 ноября 2026 года. Область: исходники capital-platform-demo, конфигурация локального запуска, тесты, документация и набор файлов Git. Независимый пентест и production-развёртывание не выполнялись.

## Готовность

Подготовлен staged-набор на ветке main и архив из 97 исходных файлов, включая четыре скриншота. Коммит с персональной идентичностью автора не создавался. Исходники подготовлены к первому коммиту и публикации в отдельном репозитории `capital-platform-demo`. Это самостоятельный демонстрационный проект, не коммерческий заказ. До передачи как полностью воспроизводимого Docker-примера требуется первый успешный удалённый CI и проверка писем в Mailpit на поднятом контейнерном стенде. Публичный GitHub-репозиторий не создавался, push не выполнялся.

## Не выполнено локально

- Сборка Docker-образов: Docker Engine отсутствует. Наличие standalone Compose позволяет проверить конфигурацию, но не заменяет сборку.
- Запуск PostgreSQL, Redis и Mailpit: соответствующие серверы отсутствуют. Подготовлен CI; его наличие не считается успешным прогоном.
- Проверка блокировок строк и конкурирующих транзакций PostgreSQL: SQLite-тесты не подтверждают поведение FOR UPDATE при конкуренции.
- Доставка настоящего SMTP-письма через Mailpit и переход по ссылке из него. Почтовая логика проверена тестами со штатными уведомлениями и подменой транспорта.
- Выполнение GitHub Actions: репозиторий пока не опубликован.
- Проверка внешнего HTTPS-развёртывания, нескольких браузеров, нагрузочное тестирование и независимый security review.

## Архитектурная оценка

Для небольшого демонстрационного проекта разделение достаточное: HTTP-контроллеры, отдельный FormRequest, модель с преобразованием типов, middleware и страницы Vue с общим каркасом. Избыточные сервисные и repository-слои ради количества файлов не добавлялись. Авторизация выполняется на сервере; клиентские props ограничены белыми списками. Административная операция блокировки и запись аудита остаются в одной транзакции.

Ограничения сохранены явно: artisan serve предназначен для локальной демонстрации, Redis не является долговременным хранилищем, базовые Docker-теги не закреплены digest. Наличие безопасного локального профиля не заменяет настройки production.

## Что требуется после публикации

1. Создать отдельный публичный репозиторий capital-platform-demo с выбранной пользователем Git-идентичностью и отправить подготовленные файлы.
2. Дождаться обоих заданий CI, включая Docker; исправить возможные ошибки, которые нельзя было воспроизвести без Engine.
3. Проверить письма в Mailpit на поднятом стенде.
4. Передавать заказчику ссылку, README и фактический статус CI. Пароль конкретного стенда передавать отдельно.
