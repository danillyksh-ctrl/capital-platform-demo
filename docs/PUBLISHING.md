# Публикация capital-platform-demo

Проект уже опубликован: https://github.com/danillyksh-ctrl/capital-platform-demo. Повторно создавать этот репозиторий не требуется. Итоговые результаты: [PUBLICATION.md](PUBLICATION.md). Следующие команды создания оставлены как справочный порядок первоначальной публикации.

## Что подготовлено

Исходники, lock-файлы, миграции, тесты, README на русском, четыре настоящих скриншота, Docker Compose и GitHub Actions. Это самостоятельный демонстрационный проект, не ранее выполненный коммерческий заказ.

В репозиторий не должны попадать реальные `.env`, зависимости, SQLite, дампы, логи, приватные ключи, локальные инструменты и созданные архивы. Проверяйте список Git, а не всё содержимое рабочего каталога.

## Локальная проверка перед push

```bash
php scripts/check-publication.php
php scripts/check-phpdoc.php
composer validate --strict
vendor/bin/pint --test
php artisan test
npm run format:check
npm run build
git diff --cached --check
git diff --cached --stat
```

Скрипт публикации ищет запрещённые пути и известные сигнатуры ключей, но не доказывает отсутствие произвольного неизвестного секрета. Дополнительно просмотрите staged diff. Пароли встречаются только как явно тестовые строки в тестах и одноразовая конфигурация CI. Пароли запуска берутся из `.env` и не публикуются.

При использовании ZIP без каталога Git сначала выполните git init -b main, затем git add .. После этого работают проверки публикуемого набора файлов.

До первого коммита настройте собственные имя и email Git. Для приватности используйте noreply-email, выданный GitHub в настройках аккаунта. Идентичность автора не подставляется автоматически.

## Создание нового публичного репозитория

На GitHub создайте пустой репозиторий **capital-platform-demo**, видимость Public, без автоматически создаваемых README и .gitignore. Затем:

```bash
git add .
git commit -m "Prepare Laravel and Vue portfolio demo"
git branch -M main
# Замените YOUR_GITHUB_LOGIN на свой логин:
git remote add origin https://github.com/YOUR_GITHUB_LOGIN/capital-platform-demo.git
git push -u origin main
```

Альтернатива с авторизованным GitHub CLI после локального коммита:

```bash
gh repo create capital-platform-demo --public --source=. --remote=origin --push
```

Если origin уже существует, сначала проверьте `git remote -v`; не меняйте его вслепую. Секреты для CI не нужны: оба задания создают изолированные демонстрационные окружения.

## После публикации

- Дождитесь обоих заданий CI: `test` и `docker`.
- Проверьте загрузку всех скриншотов на странице README.
- Включите GitHub secret scanning / push protection, если доступны для аккаунта.
- Для защиты main задайте обязательные успешные проверки CI и запретите прямые push после начальной публикации.
- Не добавляйте бейдж успешного CI до появления реального результата.
- На отдельном локальном стенде проверьте получение и переход по письмам подтверждения и восстановления через Mailpit.

Рекомендуемое описание репозитория:

> Самостоятельный демо-проект: финансовый личный кабинет на Laravel 13, Vue 3 и Inertia. Авторизация, роли, аудит, тесты, PostgreSQL, Redis и Docker.

Рекомендуемые topics: `laravel`, `vue`, `inertiajs`, `php`, `postgresql`, `redis`, `docker`, `portfolio`.
